# ozonclient

[![tests](https://github.com/ogkobz/ozonclient/actions/workflows/tests.yml/badge.svg)](https://github.com/ogkobz/ozonclient/actions/workflows/tests.yml)

Клиент Ozon Seller API на Python: реестр методов с версиями, защита от случайной записи в боевой магазин, соблюдение лимитов и понятные ошибки.

Библиотека закрывает ту часть работы с API, которую иначе пишешь заново в каждом проекте, и не лезет в бизнес-логику — она у каждого продавца своя.

## Зачем

Четыре вещи, о которые спотыкаешься, пока не наступишь.

**Тестовая среда есть, но рассчитывать на неё нельзя.** Формально у Ozon она существует — отдельный адрес `cb-api.ozonru.me`, изолированный от реальных данных. Доступ выдают по заявке, и на профильных форумах разработчики пишут, что ждут его неделями без ответа. Поэтому работать приходится в рабочей среде, а про неё в документации сказано прямо: «Рабочая среда — это ваш магазин. Все отправленные запросы, кроме информационных, могут изменять данные в личном кабинете и на сайте Ozon». Опечатка в теле запроса к `/v1/product/import/prices` меняет цены живого магазина немедленно, и откатить это нечем.

Поэтому здесь изменяющие методы **запрещены по умолчанию**. Чтобы что-то записать, клиент создаётся с `allow_writes=True` — осознанным действием, а не по невнимательности.

**Версия зашита в путь, и угадать её нельзя.** Список товаров живёт в `/v3/product/list`, характеристики — в `/v4/product/info/attributes`, цены — в `/v5/product/info/prices`, экземпляры — в `/v6/…`. Никакой закономерности нет. Промах версией возвращает `method is not allowed`, то есть выглядит как «такого метода не существует», хотя метод есть.

**Ошибки различаются текстом, а не кодом.** `Circle is open` — временная блокировка, пройдёт сама через несколько минут. `Api-key is deactivated` — не пройдёт никогда. Приходят одинаково. Клиент разбирает текст и повторяет только то, что имеет смысл повторять.

**Ключ живёт три месяца**, и дату окончания видно только через `/v1/roles`. В самом ключе её нет — в отличие от JWT у Wildberries. Интеграция умирает тихо, в день истечения.

## Установка

```bash
pip install -e .
```

Зависимость одна — `requests`. Ядро от неё не зависит: сетевой слой подменяемый.

## Использование

```python
from ozonclient import OzonClient

client = OzonClient("123456", "ваш-api-key")

# Чтение работает сразу
cards = client.call("product_list", {"filter": {"visibility": "ALL"}, "limit": 100})
prices = client.call("prices_info", {"limit": 100})
orders = client.call("fbs_unfulfilled", {"dir": "ASC", "limit": 50})

# Запись — только с явного разрешения
client.call("prices_import", {...})
# OzonWriteBlockedError: метод изменяет данные магазина, а запись не разрешена.
# Рабочая среда Ozon — это живой магазин: вызов подействует сразу.

writer = OzonClient("123456", "ваш-api-key", allow_writes=True)
writer.call("prices_import", {"prices": [...]})
```

Путь и версия берутся из реестра по короткому имени — руками их писать не нужно.

## Срок действия ключа

```python
info = client.key_info()
print(info.days_left)   # 47
print(info.roles)       # ('admin',)

client.ensure_key_alive(warn_days=14)   # предупредит в лог, если осталось мало
# OzonKeyExpiredError, если ключ уже мёртв
```

Эту проверку стоит повесить в мониторинг. Ключ истекает молча, и первым симптомом обычно становится остановившаяся выгрузка остатков.

## Батчи

Ozon принимает до 100 объектов за раз и на превышение отвечает ошибкой, а не обрезает молча:

```python
results = writer.call_batched("stocks_update", stocks, key="stocks")
```

Список режется по лимиту метода, куски уходят по очереди.

## Обработка ошибок

```python
from ozonclient import OzonAuthError, OzonTemporaryError, OzonValidationError

try:
    client.call("product_list", payload)
except OzonAuthError as exc:
    ...   # ключ мёртв, деактивирован или без нужной роли — чинить в кабинете
except OzonValidationError as exc:
    ...   # запрос не пройдёт и со второй попытки: exc.details скажет почему
except OzonTemporaryError as exc:
    ...   # это клиент уже повторил сам, сюда дойдёт только если не помогло
```

Повторы по временным ошибкам и лимиту клиент делает сам. Для `Circle is open` пауза длиннее обычной — Ozon пишет, что метод восстанавливается «в течение нескольких минут», и долбить его раз в секунду бессмысленно.

## Лимиты

50 запросов в секунду на один Client-Id. Ozon не сообщает состояние лимита в заголовках, поэтому окно считается на своей стороне — скользящее, на секунду. У отдельных методов бывают более узкие ограничения:

```python
client.limiter.set_method_limit("product_import", 5)
```

## Что внутри

| Модуль | Отвечает за |
| --- | --- |
| `methods.py` | Реестр методов: путь с правильной версией, признак записи, лимиты батчей |
| `errors.py` | Иерархия исключений и разбор ошибки по тексту, а не только по коду |
| `ratelimit.py` | Скользящее окно на Client-Id и на отдельные методы, потокобезопасно |
| `client.py` | Сборка: проверка записи, маршрут, паузы, повторы, срок ключа, ожидание задач |

## Тесты

```bash
python -m pytest
```

98 тестов, ни один не ходит в сеть: транспорт и часы внедряются через параметры, поэтому проверка повторов по `Circle is open` занимает миллисекунды вместо тридцати секунд ожидания.

Честная оговорка: тесты идут на моках по документации. Против живого кабинета продавца библиотека не проверялась — своего кабинета у автора нет.

## Границы

Методы не обёрнуты по одному: их сотни, они меняются и живут в разных версиях. В реестре собрано то, что нужно для типовой интеграции — товары, цены, остатки, заказы FBO и FBS, склады, возвраты, акции, категории. Добавить свой метод — одна строка:

```python
from ozonclient.methods import METHODS, Method

METHODS["my_method"] = Method("/v1/some/new/method", writes=True)
```

Асинхронного клиента пока нет. Точка расширения под него уже есть: `Transport` — это протокол, ядро на `requests` не завязано.
